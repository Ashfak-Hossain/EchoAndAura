# source-command-wrap

Use this skill when the user asks to run the migrated source command `wrap`.

## Command Template

1. Run `pnpm verify`. If it fails, stop and report; do not commit.
2. Prepend a dated entry to `notes/PROGRESS.md`: what was done, decisions made,
   the next slice, and any blockers.
3. If a non-obvious architectural choice was made this session, add an ADR:
   a new file in `docs/decisions/` from `TEMPLATE.md`, and its row in that
   folder's `README.md` (README → Adding an ADR).
4. Show the diff summary and propose a conventional commit message
   (`feat(scope): ...`, `fix(scope): ...`, `chore(scope): ...`). Never include
   AI/tool attribution, "generated by" wording, or `Co-Authored-By` trailers.
5. Before committing, ask who owns the commit and push for this change:
   - If the user owns them, do not commit or push. Wait for the user to confirm
     the branch is pushed, then open the pull request when requested.
   - If the user explicitly delegates them, stage, commit, push, and open the
     pull request when requested.
